# 仓库工作流

本文说明本仓库怎么用：补丁怎么生成、基线怎么固定、技术债怎么登记。

## 1. 三层结构

```
上游主线 Linux（6.12.115）
        ↓  git 提交，基线用标签固定
kernel-src/          我们的内核源码树（独立 git 仓库，3.3 GB，不进本仓库）
        ↓  git format-patch
patch/*.patch        与主线的全部差异，进本仓库
        ↓  a3-mkboot.sh 打包
images/*.img         boot 镜像（不进本仓库）
```

## 2. 基线用标签，不用分支（重要）

分支会随着后续提交前进，`format-patch` 的结果会变，别人就复现不出同一套补丁。
所以基线一律用**创建后不再移动的标签**：

```
base-6.12.115     上游 6.12.115 的提交（03bae623e），所有补丁相对它生成
a3-wip-<日期>     我们某个工作状态的快照标签，每整理一次打一个
```

规则：

```
· 不要删除、不要移动 base-* 标签
· 需要改基线（比如升级到 6.12.120）时，新建 base-6.12.120，
  在文档里写明从哪个标签起换了基线，不要覆盖旧的
· a3-wip-* 标签只增不改；有新进展就打新日期
```

## 3. 生成/更新补丁

```sh
cd kernel-src

# 1) 确认基线标签存在
git tag | grep base-6.12.115

# 2) 把当前工作提交（注意：只加自己的文件，不要把厂商无线代码加进来）
git ls-files --others --exclude-standard \
  | grep -vE '^(drivers/net/wireless|drivers/staging/btif)' | xargs -r git add --
git diff --name-only base-6.12.115 | xargs -r git add --
git commit -m "a3: 说明这次改了什么"

# 3) 打快照标签
git tag -f a3-wip-$(date +%Y%m%d)

# 4) 导出补丁
rm -f ../patch/*.patch
git format-patch --no-signature -o ../patch \
  base-6.12.115..a3-wip-$(date +%Y%m%d)
```

## 4. 从补丁还原

在干净的主线 6.12.115 源码树上：

```sh
cd linux-6.12.115
git am /path/to/repo/patch/*.patch
```

注意补丁顺序即文件名顺序，`git am` 会自动按序应用。

## 5. 提交本仓库

本仓库根目录就是 `/opt/oppoa3`，但同目录下有 3.3 GB 内核源码和 3.2 GB 镜像，
**绝对不能跑 `git add -A` 或根目录 `git status`**——构建机的页缓存会被撑爆并重启。

只加明确路径：

```sh
cd /opt/oppoa3
git add README.md .gitignore patch docs script workflow
git commit -m "docs: ..."
git push
```

查看状态也只查这些路径：

```sh
git status --porcelain -- patch docs script workflow README.md
```

## 6. 技术债表

| 编号 | 内容 | 位置 | 为什么先这样 | 影响 | 去掉的条件 |
| --- | --- | --- | --- | --- | --- |
| D1 | 触摸走 i2c-gpio 而不是硬件 i2c0 | `a3-touch-i2cgpio-dts.py` | 本机型 i2c0 硬件控制器不驱动 82/83 引脚，软件模拟是唯一可用路径 | 每次读取约 2.3 ms（受 gpiod 开销限制），轮询 6 ms，占约 40% 单核 | 查清 i2c0 引脚配置问题后换回硬件控制器 |
| D2 | 关掉自动熄屏（`idle-delay=0`） | 用户 kesry 的 dconf | 面板断电后触摸需要重新初始化，自愈逻辑未定稿 | 不省电；真实"熄屏再亮屏"未验证 | 触摸自愈稳定可用 |
| D3 | 触摸点解析只读 13 字节（2 条记录） | `a3-nt36672.c` | 降低单次 i2c 传输时间 | 最多同时支持 2 指 | 硬件 i2c 可用后恢复读 65 字节 |
| D4 | 电量用库仑计 + 手工种子 | `a3_battery.c` | MT6357 的 CAR 累加器已被复位（实测 ≈1.8 mAh），没有硬件基准 | 重装系统后初始电量可能不准 | 读 NVRAM 里的电池模型（qmax）重新标定 |
| D5 | 厂商无线栈 909 个文件不入库 | `kernel-src/.gitignore` | 体积大、版权不明 | 需要额外一步导入才能编译 WiFi | 上游有可用的 MT6631/WMT 支持 |
| D6 | `a3-bootstate.service` 仍带 `sleep 2` | `/etc/systemd/system/` | 原本是 sleep 30，用来抓开机快照，已缩短 | 开机多 2 秒 | 确认不再需要开机快照后删除该服务 |
| D7 | 早期诊断提交（panic 探针）仍在历史里 | kernel-src 提交 0003~0011 | 当时用来二分静默启动问题 | 补丁里包含这些噪音提交 | 有空时整理成干净的历史 |

## 7. 每次改动的最低要求

```
1. 一次只改一个变量
2. 刷机后必须真机验证，并记录证据（dmesg 关键行、命令输出）
3. 验证通过的镜像保留 md5
4. 出问题的镜像记录现象，不要删
5. 改动完成后当天更新文档，不要攒到最后
```
